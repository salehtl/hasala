# Break-UI report, 2026-10-28

Method: Emil Kowalski's break-ui skill. The app was run with plausible worst-case data at the mock boundary (`MayaWorst`, `MayaWorstTexts`, `mayaEmpty`, `mayaOne`, `mayaHuge`, and the worst, one, empty and huge identities). Each screen was checked at the default text size and at accessibility3 (AX XXXL). The website was checked at 320, 375, 640, 768, 1024 and 1440 px against a local mock API. Fixture commit: `b0ae1a4` on `worktree-break-ui`. All data is synthetic.

Severity: **Broken** means content cannot be read, an action cannot be reached, or the screen shows wrong data. **Ugly** means it can be read but looks wrong. **Fragile** means it is fine now but one realistic step from breaking.

Evidence: "seen" means a screenshot confirms it. "code" means it was inferred from the code, because the screen needed scrolling, taps or typing, which the simulator tools could not do (refer to "Not covered").

Finding IDs in square brackets are the track IDs (A = account, B = profile/bills/accounts/mail/texts/setup, C = home/plan/insights/widgets, D = activity/review/search, WEB = website).

## Part 2: Decisions

1. Greeting name (row 8). I recommend the full display name: name parsing across Arabic and Latin conventions will keep being wrong for someone.
2. Account dock (rows 7, 30). I recommend moving the dock inline at AX sizes only, and a hard bottom scroll edge. This keeps the Paper layout at standard sizes and the Liquid Glass behaviour.
3. Own-address rows (row 33). I recommend two lines with middle truncation for the row (a 254-byte address still fits) and a full wrap for the read-only fields.
4. Email in prose (row 34). I recommend its own line, because it also makes the address easy to check on the approval sheet.
5. Multi-alert paste (row 102). I recommend a warning that keeps the first alert for the beta, because splitting changes how the text key and dedupe work.
6. Foreign split (row 3). I recommend blocking Split for currencies that do not use 2 minor digits until AmountEntry takes a minorDigits parameter. It is a small change, and these spends are rare.
7. Add transaction at AX3 (row 19). I recommend capping the dock button at accessibility1 and collapsing the keypad while the merchant field has focus.
8. To review card scope (row 60). I recommend the period scope, to match the Review tab and its "N more in earlier months".
9. Plan split labels (row 12). I recommend the stacked legend whenever a share is under about 10%. It is already built for AX sizes and never collides.
10. Bill name (row 46). I recommend 2 lines on the card and the full name in the detail hero.
11. List title with place (row 65). I recommend 2 title lines, because the place is what tells two branches apart.
12. Arabic query (row 68). I recommend changing the copy only, unless the merchant dictionary already has Arabic names to use as aliases.
13. Freeze copy (row 11). I recommend conditional copy only, with no server change. It matches the documented design and the server's same-answer rule.
14. Unsorted spending on Home (row 69). I recommend a one-line "Not sorted" row under the tiles, not a fourth tile. It fits the existing Not counted rows.
15. Pace overflow (row 74). I recommend shrinking it to fit inside the gutter (8-10 pt), so the bleed reads as intended.
16. Website success email (row 89). I recommend stacking the label over the value, because the confirmation should show the whole address as it was typed.
17. Commas in bank names (rows 27, 125). I recommend a precise message for now. Accepting commas needs a server charset change and fixtures.
18. Website rem (row 129). I recommend converting the type tokens first, as separate later work. WCAG 1.4.4 is already met by page zoom.
19. Rules list (row 101). I recommend a 2-line clamp with "+N more", and the full list in the rule detail.
20. Review list length (row 117). I recommend virtualising (lazy) over paginating.

## Not covered

- **No touch, scroll or typing in the simulator.** The iOS Simulator control tool needs a full Xcode selection (owner: `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`), and simctl has no input injection. Only the first viewport of each screen was seen. Rows marked "code" are inferred, and these were not checked:
  - Home widgets below Budget pace, Plan rows below Groceries and the Insights lenses.
  - The Settings rows, Your requests, the set-aside rows, Recently paid and the Security devices.
  - Every foreign-currency row (JPY, KWD, OMR, USD) in Activity and Review.
  - Typed values: Arabic-Indic code digits, pasted invites, emoji passwords and bank names.
- **No stutter measurements.** Scrolling performance under mayaHuge was not measured. Only the time to first render was compared.
- **Not reachable from the screen launcher:**
  - The WidgetKit extension (system and Lock Screen widgets, the entity picker).
  - The project editor, Add transactions, the Insights drill, Move money Show all, the Categories segment, Exchange rates, Name edit and the recurring sheets.
