# Runbook: the Beta App Review demo account and reviewer codes

Apple's Beta App Review needs two things from us before an external
TestFlight build can ship:

- a **demo account** it can sign into, with data on its screens;
- **invite codes**, so a reviewer can also create an account of their own.

Both come from **review invites**. A review invite is an ordinary printed
invite with one difference: the account it creates is a *review account*.
`GET /api/v1/account` reports `review_account: true` for it, and only then
(and only while the account has no transactions) does the app offer
**"Use sample data"** on setup's email step (the "Read-only Gmail, on your
iPhone." screen). Nothing else about a review account differs, and the flag
has no other effect on the server.

Every command below runs on the QA host as the operator, through
`sudo hasala-admin` (it runs `hasalad` in a sandbox as the runtime role and
logs the mode, never the arguments). Values in angle brackets are
placeholders; nothing real belongs in this file.

| Placeholder | What it is |
| --- | --- |
| `<API>` | the public API origin, `https://api.<domain>` |
| `<REVIEW_ADDRESS>` | the demo account's address: a role address on the project domain that Email Routing forwards to the operator |
| `<DEMO_NAME>` | the demo account's display name (a made-up person) |
| `<OLD_ACCOUNT_ID>` | the previous demo account's id, if one exists |
| `<ACCOUNT_ID>` | an account id (36 lowercase characters) |
| `<INVITE_ID>` | the first 8 hex characters `invite list` prints for an invite |

## 0. Before you start

Do none of this while a build is **In Review**: no deploy, no purge, no key
change. A review can take days, and a reviewer who meets a 410 or an empty
account rejects the build.

1. The API answers:

   ```sh
   curl -s <API>/api/v1/healthz        # {"status":"ok","db":"ok"}
   curl -s <API>/api/v1/meta           # "rp_id" is the website's domain
   ```

2. Email reaches the review address. Queue a test email and wait for it to
   arrive (the worker in `serve` sends it; the CLI has no network):

   ```sh
   sudo hasala-admin email test <REVIEW_ADDRESS>
   ```

   If it does not arrive within a few minutes, fix the sender (Cloudflare
   Email Service, SPF and DKIM on the domain) or the routing before going on.
   Path A below needs no email, but creating the demo account and Path B do.

3. You have a spare **physical** iPhone with a device passcode set and the
   current build installed from the internal TestFlight group. Passkeys do not
   work against a local server, and the demo account uses a password anyway.

## 1. Remove the previous demo account (if there is one)

The account's id is on its redeemed invite (`by=` in the list):

```sh
sudo hasala-admin invite list
sudo hasala-admin purge-user <OLD_ACCOUNT_ID> --confirm <OLD_ACCOUNT_ID> --dry-run
sudo hasala-admin purge-user <OLD_ACCOUNT_ID> --confirm <OLD_ACCOUNT_ID>
```

A purge also queues the "Your Hasala account was deleted" email to the
account's address (here, the review address); the worker in `serve` sends it.

## 2. Mint the demo account's invite

```sh
sudo hasala-admin invite mint --review --note demo --ttl 336h
```

The code is printed **once** (only its hash is stored). Keep it only until
step 3 uses it.

## 3. Create the demo account on the spare iPhone

1. **Get started** → **Join with an invite** → type the code → **Continue**.
2. Name `<DEMO_NAME>`, address `<REVIEW_ADDRESS>` → **Continue** → the email
   code arrives → type it.
3. "How do you want to sign in?": **Use a password** → **Continue with a
   password** → a password of at least 20 characters, generated by and saved
   in the password manager → **Create account**.
4. The 12 recovery words: **Show my 12 words**, tap the card to show them, and
   save them in the password manager entry, in order, exactly as shown. Then
   **I've written them down** (there is no word check) and **Continue** on
   "Your account is ready."
5. "Which bank do you use?": pick a supported bank → **Continue with 1 bank**.
6. "Read-only Gmail, on your iPhone.": **Use sample data** (it appears because
   the account is a review account and has no transactions). Do not tap
   **Continue with Google** under it.
7. "A nudge when money moves.": **Not now**. Then **Go to Home** on "You're
   set".
8. Check Home shows the sample month and the **Sample data** label, and the
   **Review** tab says 6 to sort.

Then confirm the server side:

```sh
sudo hasala-admin invite list        # the demo invite: redeemed=yes by=<ACCOUNT_ID>
sudo hasala-admin account review <ACCOUNT_ID> on --confirm <ACCOUNT_ID>   # prints "(was on)"
```

`account review … on` is only a check here: the review invite already set the
flag, so it changes nothing and prints `(was on)`. Use it to set the flag on
an account that was not created from a review invite.

## 4. Mint the reviewers' codes

Two codes, one per reviewer attempt, each printed once:

```sh
sudo hasala-admin invite mint --review --note app-review --ttl 336h
sudo hasala-admin invite mint --review --note app-review --ttl 336h
```

## 5. App Store Connect: Test Information

- **Sign-in required**: yes. User name `<REVIEW_ADDRESS>`, password from the
  password manager.
- **Review notes** (keep them short and literal):
  - This app needs a device passcode (Settings › Face ID & Passcode).
  - Path A, the demo account: Sign in → the address and password above →
    when asked for the recovery phrase, paste the 12 words (listed here
    verbatim, in order). Home shows sample data.
  - Path B, a new account: Join with one of the two invite codes (listed
    here) → any address you can read → the emailed code → "Use a password"
    → keep the 12 words and tap "I've written them down" → pick a bank →
    on the Gmail screen choose "Use sample data". Gmail is optional; Google
    shows an "unverified app" screen, so please skip it.
  - The Review tab holds the transactions Hasala could not sort on its own:
    "Start" opens them as cards; swipe or tap a pill to sort each one.
  - "Use sample data" appears only for review accounts: it fills the app with
    a sample month so the screens have something to show. There is no email
    behind those transactions.
  - To try account deletion, delete an account you created with Path B
    (Profile › Delete your account). Please do not delete the demo account:
    other reviewers sign in to it.

## 6. While the build is in review

- Watch `<API>/api/v1/healthz` for the whole review.
- No deploys, purges or key changes (step 0).
- Watch the server log for `429` answers to reviewers' requests.

### If the demo account is deleted during the review

A reviewer may delete the demo account despite the notes. Its devices then
get `410`, the review address receives the "account was deleted" email, and
`invite list` no longer names an account (`by=`) on the demo invite.
Re-create it at once, because the next reviewer signs in with the credentials
in Test Information:

1. Mint a new demo invite (step 2) and create the account again on the spare
   iPhone (step 3), with the same address, a **new** generated password and
   the **new** 12 words (the old ones belong to the deleted account).
2. Check it (`invite list`, `account review … on`), as in step 3.
3. Update Test Information in App Store Connect: the password and the 12 words
   in the review notes. If App Store Connect does not let you edit them while
   the build is in review, reply to the review in App Store Connect with the
   new details.
4. Rotate the password-manager entry: the old password and words are dead.

## 7. After the verdict

1. Revoke the reviewer codes that were not used:

   ```sh
   sudo hasala-admin invite list                 # state active, review=yes
   sudo hasala-admin invite revoke <INVITE_ID>
   ```

2. Accounts reviewers created (Path B) are listed with `by=` on their
   redeemed invites. A reviewer may have deleted theirs already; purge any
   that remain (each purge emails "Your Hasala account was deleted" to the
   address the reviewer signed up with):

   ```sh
   sudo hasala-admin purge-user <ACCOUNT_ID> --confirm <ACCOUNT_ID>
   ```

3. Keep the demo account for the next build's review, or purge it (step 1).
   To keep the account but stop it being a review account:

   ```sh
   sudo hasala-admin account review <ACCOUNT_ID> off --confirm <ACCOUNT_ID>
   ```

4. Remove the recovery words and the password from the review notes when the
   account is purged, and rotate the password-manager entry.
